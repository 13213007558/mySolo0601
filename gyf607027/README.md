# 婴幼儿睡眠观察复核墙 - 门店售后版

母婴门店店长的换班交接工具。所有操作在一条时间线上完成，换班后能看到上一轮完整处理记录。

---

## 店长日常操作流程

### 1. 按手机号筛选

首页顶部的搜索框输入手机号（支持模糊匹配），比如输入 138，会筛选出所有家长手机号包含 138 的案例。

页面右上角会显示「共 X 条」，这个数字 = 导出的条数，绝不会差一条。

### 2. 导出给客服核对

筛选完手机号后，点击「导出 CSV」按钮，浏览器会自动下载 CSV 文件。

验证条数一致的方法：
- 页面显示「共 N 条」
- 打开 CSV 文件，除了表头，应该正好是 N 行数据
- 两者完全一致，没有偏差

### 3. 查看时间线（换班交接）

点击任意案例卡片，进入详情页：
- 材料列表：所有录入的材料
- 时间线：从创建到关闭的完整处理记录，包括操作人和状态变化
- 审计记录：即使操作人信息缺失，审计也会保留，方便主管复查

## 触发异常场景

### 场景 1：已关闭案例追加材料（部分成功机制）

操作步骤：
1. 打开一个「已关闭」状态的案例（样例中的 SLP202606010001 小宝）
2. 点击「+ 录入材料」
3. 添加 3 份材料：
   - 材料 1：类型选「补充说明」，标题随便填 -> 允许
   - 材料 2：类型选「睡眠日志」，标题随便填 -> 拒绝
   - 材料 3：类型选「随访记录」，标题随便填 -> 允许
4. 点击「提交材料」

预期结果：
- 页面提示「部分成功」
- 成功 2 / 共 3
- 材料列表中成功的两条会带有「已关闭后追加」标记
- 时间线会新增一条「追加材料（部分成功）」事件

规则：已关闭案例仅允许追加「补充说明」「附加照片」「随访记录」三种类型，其他类型会被拒绝。

---

### 场景 2：审计找不到处理人（必须保留审计）

操作步骤：
1. 点击「+ 新建案例」
2. 填写宝宝姓名和手机号（必填）
3. 操作人姓名那一栏留空，什么都不要填
4. 点击「创建案例」

预期结果：
1. 案例创建成功
2. 进入案例详情，翻到最底部「审计记录」
3. 可以看到一条审计记录，操作人显示为「操作人缺失」
4. 同时时间线上也会有相同标记
5. 记录没有丢失，主管可以复查这条操作

同样可以在「录入材料」「退回补充」「关闭归档」等任何操作时留空操作人姓名，都会触发审计保留机制。

---

### 场景 3：提交复核失败 - 没有材料

操作步骤：
1. 新建一个案例，只填基本信息，不要添加任何材料
2. 在草稿状态点击「提交复核」

预期结果：报错提示「请先录入至少一份材料再提交复核」

---

### 场景 4：状态流转错误

操作步骤：
1. 打开一个「已关闭」的案例
2. 注意：不会出现「提交复核」「退回」等按钮

预期结果：只有符合当前状态的操作按钮才会显示，防止误操作。

状态流转规则：
草稿 (draft) -> 提交复核 -> 复核中 (reviewing)
复核中 (reviewing) -> 退回补充 -> 补充中 (supplementing)
补充中 (supplementing) -> 再次提交 -> 复核中 (reviewing)
复核中 / 补充中 -> 关闭归档 -> 已关闭 (closed)

## 查看导出文件

### 导出步骤

1. 回到案例列表首页（点击左上角返回箭头）
2. 在搜索框输入手机号（如 13800138001）进行筛选
3. 记录页面显示的「共 X 条」数字
4. 点击「导出 CSV」
5. 浏览器会下载一个类似 sleep_review_export_xxxx.csv 的文件

### 验证条数一致

Mac 上快速验证：

```bash
wc -l ~/Downloads/sleep_review_export_*.csv | awk '{print $1 - 1}'
```

结果数字应该和页面上的「共 X 条」完全一致。

Excel / Numbers 打开：
- 打开 CSV
- 数据行数（不含表头第一行）= 页面显示条数

### CSV 包含字段

案例编号、宝宝姓名、月龄、家长手机号、门店、当前状态、创建时间、关闭时间、关闭操作人、时间线事件数、材料数
