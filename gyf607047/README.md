# 🌙 婴幼儿睡眠观察排程板（月子护理版）

> 护理主管专用：换班也能看到上一轮所有处理。一条时间线串起录入、复核、退回、整改、归档、导出。
> 服务重启后数据完整保留，审计日志永久留痕。

---

## 一、环境要求

- Node.js 18 或更高版本（命令行执行 `node -v` 可查看）
- 不需要安装数据库、不需要安装 MySQL，数据全部存在本地文件里

---

## 二、安装（只做一次）

打开终端，进入项目目录，执行：

```bash
cd /path/to/baby-sleep-board
npm install
```

看到 `added 90 packages` 字样就是装好了。

---

npm run seed

## 五、使用步骤

### 5.1 护理员录入材料
1. 打开 http://localhost:3000
2. 点击右上角 **➕ 新增记录**
3. 填写婴幼儿姓名、房间号、护理员、睡眠时间、质量、睡姿、备注
4. 点击 **保存**，状态为「录入材料（草稿）」
5. 进入详情页，可 **📷 上传照片**，每张照片可写说明

### 5.2 护理员提交复核
- 在详情页点击 **📤 提交复核**，填写操作人姓名 → 状态变为「复核中」

### 5.3 护理主管退回补充
- 在详情页（状态为复核中）点击 **⚠️ 退回补充**
- 填写退回原因和操作人（主管姓名）→ 状态回到「录入材料」
- 退回原因会出现在详情页「退回与整改记录」区

### 5.4 护理员整改补充
- 被退回后进入详情页，点击 **✅ 提交整改** 填写整改内容
- 整改内容出现在退回记录下方，有绿色标记
- 修改完记录内容、补充完照片后，再次 **📤 提交复核**

### 5.5 护理主管关闭归档
- 复核无误后，点击 **📦 关闭归档**
- 归档后记录不可修改，但所有照片、整改、时间线永久可查

### 5.6 查看时间线（护理主管复查）
- 任意记录详情页底部是 **⏱ 完整操作时间线（审计日志）**
- 每一步操作（创建、编辑、上传照片、提交、退回、整改、归档）都有时间、操作人、状态变更、备注
- 即使服务重启、进程杀掉，重启后打开详情页，时间线、照片说明、整改记录全部在

## 六、触发异常测试（模拟服务重启）

用来验证「服务重启后数据不丢失」：

### 方法一：使用内置异常测试端点

1. 确保服务在运行（`npm start`）
2. 先确保有数据（如果没有先执行 `npm run seed`）
3. 浏览器访问：**http://localhost:3000/api/crash-test**
4. 页面会显示：
   ```json
   {
     "ok": true,
     "note": "已写入审计记录。现在可以用 Ctrl+C 手动杀进程模拟服务重启..."
   }
   ```
5. **在终端按 Ctrl+C 杀掉服务**（模拟断电/崩溃）
6. 重新执行 `npm start`
7. 打开详情页，确认：照片、状态、整改记录、时间线都完整

### 方法二：手动杀进程

1. 服务运行中，直接在终端按 **Ctrl+C**
2. 再执行 `npm start`
3. 打开 http://localhost:3000，所有数据都在

## 七、查看导出

### 7.1 导出观察记录 CSV
- 列表页右上角点击 **📤 导出CSV**
- 文件自动下载，包含所有字段和照片路径、审计条数

### 7.2 导出全部审计日志
- 列表页右上角点击 **📋 导出审计**
- 或直接访问 **http://localhost:3000/api/export/audit**

### 7.3 导出单条记录的审计
- 详情页点击 **📋 导出审计** 按钮
- 或直接访问 **http://localhost:3000/api/export/audit/记录ID**
  （例如 http://localhost:3000/api/export/audit/1 ）

### 7.4 导出文件存放位置
- 所有导出的 CSV 文件都保存在项目目录的 **`exports/`** 文件夹里

## 八、数据文件位置（备份/转移用）

| 文件/目录 | 说明 |
|---|---|
| `data/app.db` | 全部数据库（记录、审计、照片索引、整改记录），**备份这个文件就够了** |
| `uploads/` | 上传的照片原图 |
| `exports/` | 导出的 CSV 文件 |

> 迁移/备份：把整个项目目录拷走即可，或至少拷 `data/` 和 `uploads/` 两个目录。

## 九、常见问题

**Q: 服务启动失败？**
A: 确认 3000 端口没被占用，或换端口：`PORT=8080 npm start`

**Q: 想清空数据重新开始？**
A: 停止服务，删除 `data/app.db`，然后重新 `npm run seed` 和 `npm start`

**Q: 照片上传失败？**
A: 检查 `uploads/` 目录是否有写入权限，单张照片不超过 10MB

**Q: 谁能归档？谁能退回？**
A: 系统不做账号密码限制（月子中心现场场景），任何人在页面上都能操作，但**每一步操作都写审计日志**，操作人姓名必填，主管可随时追责。
