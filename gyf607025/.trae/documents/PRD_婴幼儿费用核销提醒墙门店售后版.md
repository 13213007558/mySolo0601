## 1. 产品概述

婴幼儿费用核销提醒墙门店售后版是面向母婴门店店长、普通员工和主管的售后核销管理系统，解决家长追问时无法快速追溯课包流水到处理结果完整链路的痛点，同时保障普通账号与主管的数据口径一致、审计可追溯。

- 主要目标：提供从课包流水到核销处理结果的全链路追溯，支持权限分级、审计复查、幂等导入、手机号筛选导出、手工补录
- 目标用户：母婴门店店长、普通售后员工、区域主管

## 2. 核心功能

### 2.1 用户角色

| 角色 | 注册方式 | 核心权限 |
|------|----------|----------|
| 普通员工 | 门店分配账号 | 查看核销提醒列表、查看必要详情、按手机号筛选、导出数据 |
| 主管/店长 | 区域分配账号 | 全部普通员工权限 + 审计视图、完整链路追溯、查看历史记录变更 |

### 2.2 功能模块

1. **核销提醒墙首页**：提醒列表、统计卡片、角色切换、手机号筛选
2. **核销详情链路页**：课包流水 → 核销记录 → 处理结果的完整时间线
3. **审计视图（主管专属）**：操作日志、历史变更、部分成功标记、审计追踪
4. **数据导出模块**：按筛选条件导出、导出数量与页面数量严格一致
5. **手工补录模块**：补录核销记录、记录补录痕迹

### 2.3 页面详情

| 页面名称 | 模块名称 | 功能描述 |
|----------|----------|----------|
| 核销提醒墙首页 | 统计概览 | 展示待核销、已核销、异常数量，普通/主管口径一致 |
| 核销提醒墙首页 | 提醒列表 | 展示核销记录卡片，支持手机号筛选搜索 |
| 核销提醒墙首页 | 操作栏 | 导出按钮、角色切换、样例数据重导按钮 |
| 核销详情链路页 | 完整链路时间线 | 课包流水→核销记录→处理结果，时间轴可视化 |
| 核销详情链路页 | 处理结果 | 当前状态、处理人、处理时间、备注 |
| 审计视图（主管） | 审计日志 | 操作人、操作时间、操作内容、IP、变更前后值 |
| 审计视图（主管） | 部分成功标记 | 服务重启时的部分成功记录高亮 |
| 审计视图（主管） | 历史版本 | 历史记录变更对比，丢失时仍保留审计信息 |
| 手工补录页 | 补录表单 | 手机号、课包信息、核销金额、补录原因 |
| 手工补录页 | 补录痕迹 | 标记补录来源，区别于正常流水 |

## 3. 核心流程

家长来电追问 → 店长按手机号筛选 → 查看完整链路（课包流水→核销→处理结果） → 如需审计切换主管视图 → 导出给客服核对 → 如缺记录手工补录

```mermaid
flowchart LR
    A["家长追问"] --> B["店长/员工登录"]
    B --> C["按手机号筛选"]
    C --> D["查看核销提醒列表"]
    D --> E["点击查看完整链路"]
    E --> F["课包流水详情"]
    F --> G["核销记录"]
    G --> H["处理结果"]
    H --> I{需要审计?}
    I -->|是| J["切换主管角色/审计视图"]
    I -->|否| K["导出给客服核对"]
    J --> L["查看审计日志和历史"]
    L --> K
    K --> M{缺少记录?}
    M -->|是| N["手工补录"]
    M -->|否| O["流程结束"]
    N --> O
```

## 4. 用户界面设计

### 4.1 设计风格

- 主色调：暖橙色系（#FF8A3D 主色 / #FFB380 辅助），搭配深蓝（#1E3A5F）体现专业可信赖
- 按钮风格：圆角 8px，实心主色按钮 + 描边次要按钮，hover 微上浮
- 字体：标题使用 Lora 衬线体提升品质感，正文使用 Noto Sans SC 保证中文可读性
- 布局风格：卡片式布局 + 左侧导航，审计视图增加深色边条区分
- 图标：lucide-react 线性图标，状态使用 emoji 色标点缀

### 4.2 页面设计概览

| 页面名称 | 模块名称 | UI 元素 |
|----------|----------|---------|
| 核销提醒墙首页 | 统计概览 | 三色统计卡片（待办/完成/异常），数字大号加粗，底部趋势微线图 |
| 核销提醒墙首页 | 提醒列表 | 卡片网格布局，每张卡片含手机号脱敏、课包名、状态标签、时间 |
| 核销详情链路页 | 时间线链路 | 垂直时间轴，节点带状态色圆点，连线渐变，可展开折叠 |
| 审计视图 | 审计日志表 | 斑马纹表格，变更行高亮，部分成功行带琥珀色左边条 |
| 手工补录页 | 补录表单 | 分组表单，必填项红星标记，提交后弹窗显示补录痕迹 ID |

### 4.3 响应式

桌面端优先（1280px 起），平板端（768px+）列表降为单列，移动端导航折叠为底部 Tab。

## 5. 关键业务规则

1. **数量口径一致性**：普通账号与主管看到的列表数量、统计数字必须完全一致，主管只是多看到审计维度信息
2. **部分成功容忍**：服务重启导致的批量操作部分成功，需在审计中标记，不影响已成功记录
3. **审计永不丢失**：即使历史业务记录因异常丢失，审计日志必须保留供主管复查
4. **幂等导入**：样例数据重复导入时，通过 transaction_id 做幂等键，不产生重复有效记录，但保留导入审计
5. **导出一致性**：页面显示条数与导出文件条数严格一致，导出前二次校验 count
6. **手工补录标记**：补录记录带 `source: manual` 标识，审计中可追溯补录人和补录时间
