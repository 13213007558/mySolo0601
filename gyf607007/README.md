# 婴幼儿睡眠观察回访册 · 夜班交接版

全栈应用：录入材料 → 提交复核 → 退回补充 → 关闭归档 → 导出，全程一条时间线。

---

## 一、安装

需要本机已装 Node.js（建议 v18 或以上）。

在项目根目录执行：

```bash
npm install
```

> 只需要跑这一次。安装的是 Express（web 服务）和 better-sqlite3（本地数据库），无其他外部依赖。

---

## 二、启动

### 2.1 初始化数据库（只在第一次跑一次）

```bash
npm run init-db
```

看到 `数据库初始化完成` 就说明好了。数据库文件会生成在 `data/nightshift.db`，导出目录在 `exports/`。

### 2.2 启动服务

```bash
npm start
```

启动后看到：

```
婴幼儿睡眠观察回访册夜班交接版 已启动: http://localhost:3000
```

浏览器打开 **http://localhost:3000** 即可使用。

> 关闭服务：在终端按 `Ctrl + C`。

---

## 三、导入样例数据（园长试跑用）

班里准备的两份材料（旧记录 + 新补材料）外加两条故意写坏的行，都已写在脚本里。

### 3.1 跑样例脚本

```bash
npm run seed
```

会依次执行：

1. 批量导入 5 条数据（其中 2 条坏行）
2. 安安（旧记录）→ 提交复核 → 关闭归档
3. 乐乐（新补材料）→ 提交复核 → 退回补充 → 补材料 → 再提交复核
4. 萌萌（材料缺页）→ 只录入 2 页，应到 5 页
5. 故意包含不存在的 ID 执行导出，触发「导出数量不一致」审计

输出会明确打印成功几条、失败几条、坏行原因、导出文件路径。

### 3.2 刷新页面看效果

回到浏览器刷新 http://localhost:3000 ，可以看到：

- **安安**：状态「已归档」，3/3 页完整
- **乐乐**：状态「待复核」，时间线上能看到 提交 → 退回 → 补材料 → 再提交 的完整过程
- **萌萌**：状态「草稿」，红色「材料缺页 2/5」标识
- 两条坏行：不会出现在列表里，被跳过，没有拖垮任何一个正常宝宝

## 四、日常操作步骤

### 4.1 录入材料

在页面顶部可以点：

- **单条录入**：一个宝宝一个宝宝录，适合零散情况
- **批量录入**：把整理好的 JSON 粘进去一次性导入

录入时有两个特殊情况系统会处理：

| 情况 | 系统行为 |
|------|----------|
| 某一行数据缺字段（没姓名 / 没日期 / 没内容） | **该行跳过**，记一条审计，其他正常宝宝照常入库 |
| 材料缺页（总页数 > 实际录入页数） | **允许部分成功**，该宝宝记录照常入库，标记「材料缺页」，写审计 |

### 4.2 提交复核

录入后状态是「草稿」，点「提交复核」按钮，可选填备注，状态变为「待复核」。

### 4.3 退回补充

「待复核」的记录可以点「退回补充」，**必须填原因**（比如「第3页字迹模糊」），状态变为「退回补充」，同时写入审计日志。

### 4.4 补材料页

任何非「已归档」的记录都可以点「补材料」添加新的页面，系统自动更新已收页数。

### 4.5 关闭归档

「待复核」的记录点「归档」，复核人签名，状态变成「已归档」，不能再改。

## 五、触发异常并查看审计（给主管复查）

系统把所有非正常操作都写进了「审计日志」标签页。以下是你可以手动触发的异常场景：

### 5.1 触发「导入行失败」（坏行）

在「批量录入」里粘贴以下 JSON（里面故意缺了日期和姓名）：

```json
[
  { "name": "测试宝宝A", "shift_date": "2026-06-07", "total_pages": 2, "pages": [{"page_number":1,"content":"正常"}] },
  { "name": "坏行无日期", "pages": [{"page_number":1,"content":"没日期"}] },
  { "shift_date": "2026-06-07", "pages": [{"page_number":1,"content":"没姓名"}] },
  { "name": "测试宝宝B", "shift_date": "2026-06-07", "pages": [{"page_number":1,"content":"也正常"}] }
]
```

点「执行导入」。结果会是：成功 2 条（宝宝 A 和 B 都好好的），失败 2 条。切换到「审计日志」标签，能看到两条 `import_row_failed` 记录。

### 5.2 触发「部分成功 / 材料缺页」

单条录入时，把「材料总页数」填 5，下面实际只填 2 页内容，提交后该记录会显示红色「材料缺页 2/5」，审计日志里出现 `partial_import`。

### 5.3 触发「导出数量不一致」审计

点「导出选中」，然后在底部的「手动输入 record_id」里填入：`1,9999,8888`（故意写两个不存在的 ID），点「确认导出」。

导出会继续执行，但系统会：
1. 在审计日志写一条 `export_mismatch`，写明：请求了几条、实际导出几条、期望几页、实际几页
2. 在「导出历史」里，这条记录旁显示红色「数量不一致·已留审计」标记

### 5.4 查看审计日志

点页面顶部的 **「审计日志」** 标签，所有异常都会按时间倒序列出来，主管可直接复查。

## 六、查看导出文件

### 6.1 在页面上下载

点 **「导出历史」** 标签，每条记录右侧有「下载」按钮，点击即可下载 JSON 文件。

### 6.2 直接看本地文件

所有导出文件都放在项目根目录下的 `exports/` 文件夹里，文件名形如 `export_2026-06-07Txx-xx-xx-xxxZ.json`。

JSON 文件内容包含：
- 导出时间、操作人
- 请求了哪些 record_id、实际导出了多少条
- 期望总页数 vs 实际总页数
- `has_mismatch` 字段：数量不一致时为 `true`
- 每条记录的详情和每一页的内容

## 七、项目目录结构

```
.
├── package.json          # 依赖和脚本
├── server/
│   ├── app.js            # Express 主程序，定义所有 API
│   ├── db.js             # SQLite 数据库连接
│   ├── init-db.js        # 建表脚本（npm run init-db 调它）
│   └── services.js       # 核心业务逻辑：状态流转、部分成功、审计、导出
├── public/
│   └── index.html        # 前端单页应用（原生 HTML/CSS/JS，无框架）
├── scripts/
│   └── seed-sample.js    # 样例数据脚本（npm run seed 调它）
├── data/                 # 数据库文件放这里（运行 init-db 后生成）
└── exports/              # 导出 JSON 文件放这里
```

## 九、重置数据库（清空重来）

如果想彻底清空所有数据重新来：

```bash
rm -rf data/nightshift.db*
npm run init-db
npm run seed     # 可选：重新灌样例
```
