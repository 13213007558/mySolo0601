# 隐蔽工程验收复核墙

> 监理工程师不想再在群里说「差一张照片」，尤其是地下室墙筋这种一封模就看不到的活。

纯前端的隐蔽工程验收复核管理系统，专注于**证据链完整性**、**状态流转可追溯**、**角色权限明确**。

## 核心特性

### 🔒 证据链管理
- **三类证据**：验收单扫描件、现场照片、口头补签说明
- **必填校验**：提交前必须有验收单 + 现场照片，防止「差一张照片」
- **直观展示**：缺少关键证据时卡片显示黄色警告标识

### 🔄 状态流转
```
草稿 → 待审核 → 待补证 / 退回 / 可归档
        ↑            ↑       ↑
        └────────────┴───────┘   (整改/补证后重提)
```

- **严谨的状态机**：符合施工现场实际流程
- **退回原因必填**：监理退回时必须说明原因
- **每步留痕**：谁在什么时候做了什么操作，刷新后依然可查

### 👥 三种角色视图

| 角色 | 权限 |
|------|------|
| **项目经理** | 创建记录、编辑草稿、提交审核、整改后重提、补证后重提 |
| **监理工程师** | 审核、通过归档、退回整改、要求补证 |
| **资料员** | 仅可查看已归档的记录，确保归档结果不可篡改 |

### ✅ 智能校验
- **封模日期校验**：验收日期不能早于封模日期（封模后看不到隐蔽工程）
- **同一轴线重复检测**：防止同一部位重复报验
- **证据完整性校验**：提交前自动检查必需的验收单和照片

### 📊 审计追踪
- 完整的状态变更历史时间线
- 记录操作人、角色、时间、原因
- 支持全局审计视图，一目了然看到谁在什么时候把记录从「待补证」改成「可归档」

### 📄 CSV 导入导出
- 导出的归档清单**与当前筛选条件一致**
- 自动添加 UTF-8 BOM，Excel 打开中文不乱码
- 支持批量导入历史数据

## 技术栈

- **React 18** - UI 框架
- **TypeScript 5** - 类型安全
- **Zustand 4.5** - 轻量级状态管理
- **TailwindCSS 3** - 原子化 CSS
- **Vite 5** - 构建工具
- **date-fns 3** - 中文日期处理
- **lucide-react** - SVG 图标
- **papaparse 5** - CSV 解析
- **localStorage** - 浏览器本地存储

## 快速开始

### 本地启动

```bash
# 安装依赖
npm install

# 启动开发服务器（端口 5177）
npm run dev

# 类型检查
npm run check

# 构建生产版本
npm run build

# 预览生产版本
npm run preview
```

访问 http://localhost:5177/ 即可使用。

### 前端自检（推荐首次使用）

页面顶部工具栏点击绿色「自检」按钮，一键运行 **4 大类 17 项**前端自动化验证：

- 🔒 **角色权限**（5项）：项目经理创建、监理/资料员权限、资料员强制过滤、状态流转矩阵
- 📋 **证据校验**（5项）：缺证据阻止提交/归档、证据完整放行、同轴线重复、日期顺序
- 🔍 **筛选与导出**（4项）：状态筛选、关键词搜索、重置恢复、CSV导出匹配
- 📜 **审计追踪**（4项）：历史记录存在、C-D/3-4补录轨迹、退回原因必填、操作人角色记录

所有检测在浏览器本地运行，使用当前 localStorage 中的样例数据。

### 0. 初始化与样例数据

首次打开页面，系统自动加载 **6 条样例记录**，覆盖全部 5 种状态：

| # | 轴线 / 部位 / 工序 | 状态 | 特征 |
|---|-------------------|------|------|
| 1 | A-B/1-2 / 地下室负一层 / 地下室墙筋 | 可归档 | 证据齐全，完整归档流程 |
| 2 | **C-D/3-4 / 主体三层 / 梁板钢筋** | **待补证** | **核心测试用例，用于补录追踪** |
| 3 | E-F/5-6 / 主体二层 / 柱筋绑扎 | 退回 | 含退回原因：箍筋间距不达标 |
| 4 | G-H/7-8 / 地下室负一层 / 后浇带 | 待审核 | 资料齐全等待监理审核 |
| 5 | B-C/2-3 / 主体四层 / 剪力墙钢筋 | 待补证 | 缺照片，共 2 条待补证 |
| 6 | A-B/10-11 / 主体五层 / 预埋管线 | 草稿 | 可编辑的草稿状态 |

> 6 条记录对应 **9 条历史审计记录**（每条状态变更都有留痕）。

### 1. 验证：待补证筛选 = 2 条

**步骤：**
1. 以「监理工程师 李工」或「项目经理 张伟」身份登录
2. 左侧筛选面板 → 状态 → 点击「待补证」
3. 观察：
   - 统计面板显示「当前筛选：2 条」
   - 卡片区域仅显示 2 条记录：
     - C-D/3-4 梁板钢筋（待补证）
     - B-C/2-3 剪力墙钢筋（待补证）
4. 点击「重置」→ 恢复为 6 条

### 2. 验证：资料员视图 = 1 条可归档

**步骤：**
1. 左侧角色切换 → 点击「王芳 资料员」
2. 观察：
   - 顶部出现绿色提示条：「资料员视图：您当前只能查看可归档的验收记录」
   - 卡片区域仅显示 **1 条**记录：A-B/1-2 地下室墙筋（可归档）
   - 左侧筛选面板状态仅有「可归档」被选中
3. 点击「重置」筛选 → 仍只显示 1 条（硬编码强制过滤，无法绕过）
4. 记录卡片无「编辑」「提交」等操作按钮，仅可查看详情

### 3. 验证：CSV 导出随筛选变化

**步骤：**
1. 切换到任意非资料员角色
2. 点击筛选「待补证」→ 确认 2 条结果
3. 点击顶部「导出」按钮
4. 下载的 CSV 文件包含：
   - 表头 + **2 行数据**（对应 2 条待补证记录）
   - 文件带 UTF-8 BOM，Excel 打开中文不乱码
5. 重置筛选，再次导出 → CSV 包含全部 6 条记录

### 4. 验证：C-D/3-4 补录轨迹可追溯

**步骤：**
1. 在列表中找到「C-D/3-4 主体三层 梁板钢筋」记录
2. 点击卡片展开详情 → 查看「状态变更时间线」：
   - 2024-01-16 09:00 张伟（项目经理）：草稿 → 待审核
   - 2024-01-16 14:30 李工（监理）：待审核 → 待补证
     - 原因：「缺少关键照片证据，需要补充梁板钢筋验收现场照片后重新提交。」
3. 也可点击顶部「审计追踪」查看全量历史表，验证完整可追溯

### 5. 验证：证据链完整性校验

**步骤：**
1. 切换到「项目经理 张伟」
2. 展开 C-D/3-4 梁板钢筋（待补证状态）
3. 点击「补证后重提」→ 系统阻止提交，提示「缺少关键证据」
4. 展开 A-B/1-2 地下室墙筋（可归档）→ 证据齐全（验收单 + 照片）

### 6. 验证：监理退回必须填原因

**步骤：**
1. 切换到「监理工程师 李工」
2. 展开任意待审核记录 → 点击「退回整改」
3. 弹出模态框，必须填写原因才能提交
4. E-F/5-6 柱筋绑扎 记录已包含历史退回原因可供参考

### 2. 补录前后状态追踪（核心测试场景）
查看 **C-D/3-4 轴 主体三层 梁板钢筋** 这条记录：

## 设计亮点

### 工业实用风 UI
- 主色调：安全帽橙色 `#F59E0B` + 蓝图深蓝色 `#1E3A8A`
